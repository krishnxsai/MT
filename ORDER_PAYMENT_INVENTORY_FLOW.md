# MediTrack: Complete Order → Payment → Inventory Flow

## 📋 FULL PROCESS FLOW (START TO END)

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          PHASE 1: ORDER PLACEMENT                            │
└─────────────────────────────────────────────────────────────────────────────┘

1. USER STARTS AT UnifiedOrderActivity
   ├─ Selects medicines from alert/search (adds to cart)
   ├─ Selects pharmacy from nearby list
   └─ Gets location (or uses fallback if unavailable)

2. USER CLICKS "PLACE ORDER" BUTTON
   ├─ OrderConfirmationBottomSheet shows:
   │  ├─ Items: medicine names, quantities, prices
   │  ├─ Subtotal calculation
   │  ├─ Delivery fee (₹50 base + ₹5/km)
   │  └─ Total with GST (18%)
   └─ User enters delivery address

3. USER CONFIRMS DELIVERY ADDRESS
   └─ Calls viewModel.placeOrder(deliveryAddress)

4. UnifiedOrderViewModel.placeOrder() EXECUTES
   ├─ Validates: pharmacy selected ✓
   ├─ Validates: cart has items ✓
   └─ Builds OrderItem list from cart


┌─────────────────────────────────────────────────────────────────────────────┐
│                    PHASE 2: INVENTORY VALIDATION                             │
└─────────────────────────────────────────────────────────────────────────────┘

5. OrderRepository.placeOrder() CALLED
   ├─ Check: User authenticated ✓
   ├─ Check: Order has items ✓
   ├─ Check: Pharmacy selected ✓
   │
   └─ INVENTORY VALIDATION STEP
      ├─ Call: validateInventory(order)
      │
      ├─ For each item in order:
      │  ├─ Query: pharmacyInventory/{pharmacyId}_{medicineId}
      │  ├─ Get: existing quantity from Firestore
      │  ├─ Check: quantity >= requested amount
      │  │  ✓ PASS: Continue to next item
      │  │  ✗ FAIL: Return Error("Medicine X unavailable")
      │  └─ If any item fails → ABORT ORDER
      │
      └─ All items valid → Return Success


┌─────────────────────────────────────────────────────────────────────────────┐
│                    PHASE 3: ORDER CREATION IN FIRESTORE                      │
└─────────────────────────────────────────────────────────────────────────────┘

6. ORDER DOCUMENT CREATED IN FIRESTORE
   └─ Collection: /orders/{orderId}
      ├─ userId: current user ID
      ├─ pharmacyId: selected pharmacy ID
      ├─ pharmacyName: pharmacy name
      ├─ items: [
      │     {medicineId, medicineName, quantity, unitPrice, totalPrice},
      │     ...
      │  ]
      ├─ subtotal: sum of all item prices
      ├─ deliveryFee: ₹50 + (distance × ₹5)
      ├─ totalAmount: subtotal + deliveryFee + GST
      ├─ deliveryAddress: {fullAddress, latitude, longitude}
      ├─ status: PENDING
      ├─ statusHistory: [{status, changedAt, note}]
      ├─ createdAt: server timestamp
      └─ orderId: auto-generated by Firestore


┌─────────────────────────────────────────────────────────────────────────────┐
│                    PHASE 4: INVENTORY REDUCTION                              │
└─────────────────────────────────────────────────────────────────────────────┘

7. INVENTORY UPDATED AFTER ORDER CONFIRMED
   └─ Call: reduceInventory(order)
      │
      ├─ For each item in order:
      │  ├─ docId = "{pharmacyId}_{medicineId}"
      │  ├─ Query: /pharmacyInventory/{docId}
      │  ├─ Decrement: quantity -= item.quantity
      │  ├─ Firestore: FieldValue.increment(-quantity)
      │  └─ Result: Atomic decrement (no race conditions)
      │
      └─ Example:
         Before: quantity = 50
         Order:  quantity = 5
         After:  quantity = 45  ✓


┌─────────────────────────────────────────────────────────────────────────────┐
│                    PHASE 5: PAYMENT INITIATION                               │
└─────────────────────────────────────────────────────────────────────────────┘

8. ViewModel EMITS NAVIGATION EVENT
   └─ Emit: NavigationEvent.ToPayment(orderId, totalAmount)
      │
      ├─ Activity receives event
      ├─ Check: FeatureFlags.isEnabled(PAYMENT_ENABLED) → TRUE ✓
      └─ Call: launchPaymentActivity(orderId, totalAmount)

9. PAYMENT ACTIVITY LAUNCHES
   ├─ Extract intent extras:
   │  ├─ order_id: RefillOrder document ID
   │  ├─ amount: Total in rupees
   │  ├─ user_email: User's email
   │  ├─ user_phone: User's phone number
   │  └─ user_name: User's full name
   │
   ├─ Preload Razorpay SDK
   └─ Call: PaymentViewModel.createPaymentOrder()


┌─────────────────────────────────────────────────────────────────────────────┐
│                    PHASE 6: RAZORPAY ORDER CREATION                          │
└─────────────────────────────────────────────────────────────────────────────┘

10. RAZORPAY ORDER CREATED
    ├─ PaymentViewModel.createPaymentOrder() called
    ├─ Call: RazorpayRepository.createOrder()
    │
    ├─ RazorpayRepository.createOrder():
    │  ├─ Make HTTP request to Razorpay API
    │  ├─ Send: amount, currency (INR), customer info
    │  ├─ Receive: Razorpay order ID
    │  ├─ Create Firestore document at /payments/{paymentId}
    │  │  ├─ userId: current user ID
    │  │  ├─ orderId: RefillOrder ID
    │  │  ├─ razorpayOrderId: from Razorpay
    │  │  ├─ amount: in paise
    │  │  ├─ currency: INR
    │  │  ├─ status: PENDING
    │  │  └─ createdAt: server timestamp
    │  └─ Return: RazorpayOrder object
    │
    └─ UI State: OrderCreated(razorpayOrder)


┌─────────────────────────────────────────────────────────────────────────────┐
│                    PHASE 7: RAZORPAY CHECKOUT UI                             │
└─────────────────────────────────────────────────────────────────────────────┘

11. RAZORPAY CHECKOUT OPENS
    ├─ PaymentActivity.startPaymentCheckout(razorpayOrder)
    │
    ├─ Prepare checkout options:
    │  ├─ order_id: razorpayOrderId
    │  ├─ amount: in paise (₹100 = 10000 paise)
    │  ├─ currency: INR
    │  ├─ email: user email
    │  ├─ contact: user phone
    │  ├─ method: upi (can be card, netbanking, etc.)
    │  ├─ timeout: 900 seconds (15 minutes)
    │  └─ theme.color: Material Blue
    │
    ├─ User sees Razorpay UI
    └─ User selects payment method (UPI, Card, etc.)


┌─────────────────────────────────────────────────────────────────────────────┐
│                    PHASE 8: PAYMENT COMPLETION                               │
└─────────────────────────────────────────────────────────────────────────────┘

12. USER COMPLETES PAYMENT (2 paths)

    PATH A: PAYMENT SUCCESS ✓
    ├─ Razorpay returns: paymentId + signature
    ├─ Activity: onPaymentSuccess(razorpayPaymentId) callback
    ├─ Call: PaymentViewModel.handlePaymentSuccess()
    │
    ├─ Step 1: Verify payment signature
    │  ├─ Call: RazorpayRepository.verifyPayment()
    │  ├─ Verify HMAC-SHA256 signature
    │  ├─ Signature = SHA256(razorpayOrderId|razorpayPaymentId, Secret)
    │  ├─ If valid → Continue
    │  └─ If invalid → Payment verification failed (abort)
    │
    ├─ Step 2: Record payment in Firestore
    │  ├─ Call: RazorpayRepository.recordPaymentSuccess()
    │  ├─ Create transaction document at /transactions/{transactionId}
    │  │  ├─ userId: current user ID
    │  │  ├─ orderId: RefillOrder ID
    │  │  ├─ paymentId: razorpayPaymentId
    │  │  ├─ type: PAYMENT
    │  │  ├─ amount: in rupees
    │  │  ├─ status: SUCCESS
    │  │  ├─ paymentMethod: UPI (or selected method)
    │  │  ├─ razorpaySignature: signature
    │  │  └─ createdAt: server timestamp
    │  └─ Return: Success
    │
    ├─ Step 3: Update order status to CONFIRMED
    │  ├─ Call: OrderRepository.updateOrderStatus()
    │  ├─ Update /orders/{orderId}
    │  │  ├─ status: PENDING → CONFIRMED
    │  │  ├─ Add to statusHistory: {status: CONFIRMED, note: "Payment confirmed via UPI", changedAt}
    │  │  └─ paymentId: razorpayPaymentId
    │  └─ Return: Success
    │
    └─ UI State: PaymentSuccess → paymentSuccess.value = razorpayPaymentId

    PATH B: PAYMENT FAILURE ✗
    ├─ Razorpay error callback: onPaymentError(code, response)
    ├─ Call: PaymentViewModel.handlePaymentFailure()
    │
    ├─ Record failed payment attempt
    │  ├─ Call: RazorpayRepository.recordPaymentFailure()
    │  ├─ Create transaction at /transactions/{transactionId}
    │  │  ├─ type: PAYMENT_FAILED
    │  │  ├─ status: FAILED
    │  │  ├─ errorCode: from Razorpay
    │  │  ├─ errorDescription: error message
    │  │  └─ createdAt: server timestamp
    │  └─ Return error response
    │
    └─ UI State: PaymentFailed → Show error message


┌─────────────────────────────────────────────────────────────────────────────┐
│                    PHASE 9: NAVIGATION TO ORDER TRACKING                     │
└─────────────────────────────────────────────────────────────────────────────┘

13. SUCCESS: NAVIGATE TO ORDER TRACKING
    ├─ Activity result: RESULT_OK
    ├─ Extra: payment_id = razorpayPaymentId
    ├─ UnifiedOrderActivity.onActivityResult(REQUEST_CODE_PAYMENT, RESULT_OK)
    │
    ├─ Create intent to OrderTrackingActivity
    │  ├─ EXTRA_ORDER_ID = currentPaymentOrderId
    │  └─ startActivity(intent)
    │
    ├─ OrderTrackingActivity opens
    └─ User sees: Order status → CONFIRMED, payment confirmed


┌─────────────────────────────────────────────────────────────────────────────┐
│                         FINAL STATE SUMMARY                                  │
└─────────────────────────────────────────────────────────────────────────────┘

14. FIRESTORE COLLECTIONS UPDATED

    /orders/{orderId}
    ├─ Status: PENDING → CONFIRMED ✓
    ├─ statusHistory: Added payment confirmation entry
    └─ paymentId: linked to payment

    /transactions (NEW ENTRY)
    ├─ Type: PAYMENT
    ├─ Amount: total order amount
    ├─ Status: SUCCESS
    └─ References: orderId, userId, paymentId

    /pharmacyInventory/{pharmacyId}_{medicineId}
    ├─ Quantity: reduced by ordered amount
    └─ Updated after order created (PHASE 4)

    /payments/{paymentId}
    ├─ Status: CONFIRMED
    ├─ Razorpay payment ID: stored
    └─ Audit trail for compliance

## 🔐 SECURITY & VALIDATION POINTS

✓ Authentication Check
  └─ Every repository method checks: currentUserId != null

✓ Inventory Validation
  └─ Before order creation: check stock available

✓ Inventory Atomicity
  └─ FieldValue.increment() prevents race conditions

✓ Payment Signature Verification
  └─ HMAC-SHA256 with secret key (server-side validation)

✓ Firestore Security Rules
  └─ Users can only read their own orders
  └─ Pharmacy can only read their own pharmacy's orders
  └─ Orders immutable after CONFIRMED status change

✓ Idempotency
  └─ Payment recordPaymentSuccess checks for duplicates
  └─ Transaction records immutable (no updates)

✓ Audit Trail
  └─ Orders never deleted (form audit trail)
  └─ Transactions immutable
  └─ statusHistory tracks all status changes

## ⚠️ ERROR HANDLING

Inventory Validation Fails
├─ Error: "Medicine X unavailable (in stock: 3, requested: 5)"
└─ Result: Order NOT created, user returns to cart

Payment Verification Fails
├─ Error: "Payment verification failed"
└─ Result: Transaction marked FAILED, order remains PENDING

Location Unavailable
├─ Fallback: Use default coordinates (Delhi)
└─ Result: Order proceeds with fallback location

User Not Authenticated
├─ Error: "Not logged in"
└─ Result: All operations blocked, redirect to login

## 📋 STATUS TRANSITIONS

Order Status Flow
```
PENDING (Order placed, awaiting payment)
   ↓
CONFIRMED (Payment successful)
   ↓
PREPARING (Pharmacy prepares order)
   ↓
READY (Order ready for delivery)
   ↓
SHIPPED (Out for delivery)
   ↓
DELIVERED (Customer received)
   ↓
RETURNED (Optional)
```

Or:
```
PENDING/CONFIRMED/PREPARING
   ↓
CANCELLED (User cancels, inventory restored)
```
